## 一、结论速览

**配置面共 4 套「真源」+ 1 套用户快照，同一件事经常有 2~4 个说法；运行时再按各自代码默认兜底。**

| 真源 | 规模 | 角色 |
| --- | --- | --- |
| `config/default_config/config.yaml` | 542 个叶子键 / 764 行 | 默认值主真源（含大量行为承诺注释） |
| `guoba.support.js`（锅巴面板） | 143 field（140 精确映射 yaml，覆盖率 **25.8%**） | 表单 + 第三方文案 |
| `web/assets/js/views/config.js`（Web 配置中心） | 423 个 `form.*` 绑定（全部落在 yaml 叶子） | 主配置入口 + 前端兜底默认 |
| `README.md` 详细配置表 / `开发指南.md` | ~135 行配置表 | 用户文档（且用户配置落盘后**不含注释**，README 是唯一说明入口） |
| `utils/Config.js` 归一 + 代码内 `DEFAULT_*` | 3 个 `model/*/default-config.js` + 各读点 `??` 兜底 | 运行时事实真源 |

**确认冲突/互搏 73 条**（4 份审计原始 84 条，去重合并后）：**P0 2 条、P1 27 条、P2 44 条**。
其中 6 类根因反复出现：

1. **多源默认值分叉**：同一语义在 yaml / 锅巴 / Web / README / 代码默认里各写一套（`toolDiscovery.alwaysOn` 三源、回退模型双源、`renderScale`、`crawl.execution`、`maxTurns`、`thinking` 形状…）。
2. **父开关关着、子开关默认开**：默认配置自身不自洽（`sticker.enable=false` + `sendStickerTool=true`、`tts.enable=false` + `autoReply=true`、`comfyui.enable=false` + `command.enable=true`、`humanize.enable=false` + `allowSticker=true`）。
3. **文档/面板承诺 ≠ 运行时强制**：`debug` 是死配置、`media.passive` 无人消费、`kb.enable` 只关工具不堵入库、`render.card` 只控帮助图、沙箱权限描述过时、Stagehand 权限文案与默认相反。
4. **假值/类型陷阱**：`Number.isFinite(Number(null)) === true` 把 `null` 当 0（温度被钉 0）；`cacheControl` 布尔值 vs 三态字符串；布尔严格 `=== true` 使 `"true"/1` 静默失效；清空的数值项「设过就回不去」。
5. **归一逻辑互相覆盖**：`Config.load()` 自愈迁移会把用户清空的 `providerId` 立刻重建；清空 `modelId` 后镜像字段继续生效；两个面板各写一套私有归一（thinking 互斥、MCP 合并、masters 转数组），`Config.js` 没有统一 `normalize()`。
6. **保存即全量落盘**：任意一次保存都会把「默认值 + 用户值」整份写回用户 `config.yaml`（实测 1 次保存后用户文件含 644 个键）→ 默认值快照化，**以后版本改默认值对老用户永不生效**；而热加载 `reload()` 又不做自愈落盘，内存与文件还不一致。

## 二、P0 明细

### F1 [P0][F] 模型条目温度 `null` 被当成 0，覆盖全局 0.2

- 证据 A（写入侧）：`web/assets/js/views/config.js:474`（新建模型条目固定 `temperature: null`）、`:525`、`:2406`（弹窗保存/模板同样允许 `null` 或空串）；`utils/Config.js:158`（旧配置迁移生成的模型条目同样 `temperature: null`）。
- 证据 B（读取侧）：`apps/agent.js:1085` `const regTemperature = Number.isFinite(Number(regEntry?.temperature)) ? Number(regEntry.temperature) : null`；`Number(null) === 0`、`Number('') === 0` → 条件为真 → `regTemperature = 0`。
- 证据 C（后果）：`apps/agent.js:1161` `temperature: regTemperature != null ? regTemperature : cfg.temperature` → 模型级 0 压过全局 `0.2`；而 `config.yaml:50` 自己写着「工具调用稳定性（建议 0.1~0.3；**勿设 0 避免复读式回复**）」。
- 同源缺陷：`apps/agent.js:1328` 视觉模型条目温度同一写法；`regMaxTokens` 因多了 `> 0` 判断而免疫（说明这是漏加守卫，不是设计）。
- 影响面：**所有走「厂商/模型注册表」的用户**（即 README 推荐的引用制主路径），包括旧配置自动迁移的用户；表现为回复复读、工具调用不稳，且日志不会提示。
- 建议：读取侧改成显式判空（`v == null || v === '' ? null : Number(v)`，或统一 `numOrNull()` 工具）；写入侧 `ensureModelEntry`/迁移不要落 `temperature: null`（写 `undefined` 或省略键）。
- 置信度：高（Lead 已用 Node 复现 `Number.isFinite(Number(null)) === true`）。

### F2 [P0][P/N] 「取消/清空基础模型」与运行时静默分叉（自愈 + 镜像互搏）

三处独立证据，合并为一条：

1. **清空 `providerId` 会被立刻重建**：`utils/Config.js:141-166` `migrateBaseModel()` 的触发条件是「`providerId` 空 且 `apiKey` 非空」→ 只要历史上配过 Key（镜像字段非空），用户在 Web 选「（未选择）」（`config.js:1098`）或锅巴把 `providerId` 清空，`Config.save() → normalizeBaseModel() → migrateBaseModel()` 会按旧镜像重新登记厂商/模型并把 `providerId/modelId` 写回。
   **Lead 沙箱复现**：设置 `providerId='ptest'` 后执行 `providerId=''` → 保存后立即变回 `'ptest'`，且日志打「已把旧的主接入配置迁移为厂商…」。→ 界面上「取消选择」是个**无效操作**，且无任何提示。
2. **清空 `modelId` 后镜像残留继续生效**：`utils/Config.js:169-177` 解析失败时刻意不清空 `protocol/preset/baseURL/apiKey/model`；`:197-204` 注释自认这是「静默分叉」。复现：清空 `modelId` 后配置为 `modelId: ""`，但运行时仍用 `model: deepseek-chat` + 旧 Key，面板却显示「留空 = 默认回落」（`config.js:1323`）。
3. **`PUT /api/config` 允许写镜像字段并谎报成功**：`model/web/api.js:673-697` 只校验 `agent.*` 前缀，`agent.model/protocol/baseURL/apiKey` 均可写入且计入 `applied`；随后 `Config.save → syncBaseModel`（`Config.js:169-177`）无条件覆盖，接口仍返回「已保存（已热加载）」。

- 影响面：所有用面板做模型切换/清空的用户；「面板状态 = 运行时状态」的信任被破坏，且失效只留一条 WARN（启动时才打、去重后只打一次）。
- 建议：`migrateBaseModel` 只在「从未有过引用且是首迁移」时跑（例如用一次性 `migratedAt` 标记，或只在 `load()` 首启动跑、`save()` 不跑）；`providerId` 被主动清空时同步清空镜像并让运行时明确报「未选择模型」；PUT 拒绝镜像字段（白名单）或明确返回「已忽略镜像字段」；面板对 dangling 引用展示醒目徽标。
- 置信度：高（1、2 为 Lead 沙箱复现，3 为静态核验）。

## 三、P1 明细（按主题）

### A. 多源默认值 / 文案分叉

#### F3 [P1][O] `toolDiscovery.alwaysOn` 三源不一致 + `stableList` 让「按需发现」名不副实
- yaml 默认 12 个（`config.yaml:254-266`，缺 `context_recall`/`schedule_task`/`kb_search`/`reminder_set`，多 subagent 三件套）；代码 `DEFAULT_ALWAYS_ON` 13 个（`model/agent/Agent.js:45-46`，注释详述为何 `context_recall`/`schedule_task` 必须常驻）；锅巴说明又是第三个版本（`guoba.support.js:164`）。
- 非空 yaml 数组永远压过代码默认（`Agent.js:1461`、`apps/agent.js:1196`）→ 代码默认成死代码。
- 同时 `toolDiscovery.enable` 注释说「只常驻少数、其余检索后动态注入」（`config.yaml:252`），而同节 `stableList: true` 注释说「每轮下发全量工具定义」（`:269`）；实现是后者（`Agent.js:1544`）→ tools 数组永远全量，`alwaysOn/topK/minScore` 只影响 system 目录与 activeTools 记录。
- 建议：`alwaysOn` 留空让代码默认为唯一真源（或三方同步同一列表）；`toolDiscovery.enable` 注释改写为「控制工具目录与 tool_search 记录；stableList=true 时 schema 仍全量下发」。
- 置信度：高（Lead 已核 `_buildToolList`）。

#### F4 [P1][O/X] `renderScale` 默认值三方不一致
- yaml `3`「3=超清默认」（`config.yaml:130`）、README `3`、代码兜底 `?? 3`（`apps/agent.js:2423`、`apps/render.js:92`）— 但锅巴面板写「**2=高清（默认）**，1=普通」（`guoba.support.js:137`）、Web 面板上限文案 `1~4` 无默认说明。
- 后果：按锅巴文案主动设 2，清晰度反而低于出厂默认。
- 建议：锅巴文案改「3=超清（默认）/2=高清/1=普通」。

#### F5 [P1][O] `crawl.execution` 面板值 `host` 不在 yaml/代码词表
- 锅巴 Select 写 `value: 'host'`（`guoba.support.js:273`）；yaml/README/代码是 `local|sandbox`（`config.yaml:164`、`model/crawl/index.js:425-440` 只判 `=== 'sandbox'`，其余兜 local）。
- 后果：默认值 `local` 在下拉里没有对应项（回显空白）；用户选「宿主」写入 `host`，Web 面板又回显空白，来回保存漂移。
- 建议：面板 value 改 `local`。

#### F6 [P1][O/F] 代码兜底默认与 yaml 默认「两套值」：清空/缺键即静默换一套
- `maxTurns`：yaml 200（`config.yaml:39`）→ `apps/agent.js:1159` `?? 50` → `model/agent/Agent.js:248` `?? 90`（同字段三套默认；启动日志 `agent.js:513` 还把 `?? 50` 打出来误导排障）。
- `maxToolResultChars`：yaml 8000（`:104`）→ `apps/agent.js:1185` / `Agent.js:303` `?? 4000`（减半）。
- `multiagent.reserveTokens`：yaml 32000（`:554`）→ `apps/agent.js:1399` `|| 8000`；`sandbox.toolEvoVerifyTimeoutMs`：yaml 5000（`:499`）→ `apps/agent.js:1051` `|| 3000`。
- `chatPermission`：yaml `master`（`:209`）→ `apps/agent.js:1969/1954` `|| 'all'`，且 `_hasChatPermission`（`:1977` 起）「未知取值一律放行」→ 字段清空/拼错时**权限放宽到所有人**（安全降级）。
- 同类：`LoopGovernor` 内部默认 `timeBudgetMs=90s / tokenBudget=80k`（`model/agent/loop-governor.js:53-57`）与 yaml 30min/480k 相差一个数量级，只在 `loop` 块被整体置空时暴露。
- 建议：删掉代码侧兜底（依赖 deepMerge 后必存在）；无法删的（安全类）兜底一律取**更严**值；`chatPermission` 兜底改 `master`。

#### F7 [P1][O] 回退模型双真源：`fallbackModels[]` vs 扁平 `fallbackModel*`
- yaml 同时存在（`config.yaml:24-36`，注释分别写「多回退用数组（在此 yaml 配）」「锅巴单回退（扁平字段）」）；运行时取**并集**且数组优先、扁平追加在最后（`apps/agent.js:566-568`）。
- Web 面板只读写数组（删光后扁平仍在生效）、锅巴只读写扁平（看不到数组）→ 两个面板互不可见、用户以为删了回退其实没删。
- 附带：缺 `apiKey` 的回退条目被静默 `continue`（`:570`），无启动告警。
- 建议：收敛为单一真源（推荐数组 + 面板数组编辑器；扁平字段仅做兼容迁移后删除）。

#### F8 [P1][D/O] `utilityModel` 两个控件、两套选项集，且同页文案互相否定
- 「基础/模型」卡的 `utilityModel` 只列主厂商并写「只能选当前厂商」（`config.js:1318` 附近），「功能分配」卡可跨厂商；同一页逐行说明又写「可选任意厂商（运行时按注册表解析端点）」（`:1321-1328`）。
- yaml（`config.yaml:19`）与 model-router（支持 `llmModels[].id` / 裸模型名）都支持跨厂商 → 旧文案/旧限制未清。
- 建议：删除 `mainOnly` 残留逻辑与过时文案，统一一个控件。

#### F9 [P1][O] `cacheControl` 布尔值 vs 三态字符串
- yaml `cacheControl: false`（布尔，`config.yaml:120`）；Web 面板是三态 Select `off/auto/explicit`（`config.js`，`onFeatureSel` 同族），首屏 `false` 不在 options 内 → 显示空白；保存后类型变成字符串。
- 代码接受三态（`apps/agent.js:1203`、`Agent.js:332`），`'off'` 恰好等价 false，但配置类型在 yaml↔面板之间来回变，`=== true` 的判断点会失效。
- 建议：yaml 默认改成 `off` 字符串并注释三态；布尔 true 继续兼容但面板统一为字符串。

### B. 面板/文档承诺 ≠ 运行时

#### F10 [P1][N] `debug` 是死配置（三处文档承诺、运行时无人读）
- 承诺：yaml `debug: false`（`config.yaml:1`）、锅巴「打印工具入参/每轮 token/搜索词」（`guoba.support.js:98`）、README 同文（`README.md:253`）。

- 建议：把 `Config.get().debug` 接到 Log 级别/DevLog；否则三处一并删除并把 `devLog.enable` 上卡。

#### F11 [P1][N] `media.passive` 死配置（README 承诺可关被动工具）
- `README.md:315` 把 `passive` 描述为「被动工具（`list_group_files`/`get_group_file`/`read_attachment`）」；代码只在 `model/media/index.js:86` 算出 `passiveEnabled`，全仓无人消费；三工具在 `apps/agent.js:756` **无条件注册**，其中 `read_attachment` 是 `category:'query'`（全员可用，`model/media/tool.js:181-183`）。
- 建议：注册处按 `cfg.media?.passive !== false` 决定；或删掉该配置。

#### F12 [P1][L] `kb.enable` / `kb.crawlEnable` 只关工具注册，不堵入库与抓取
- yaml 承诺「关则不注册 kb_search、**不入库**」（`config.yaml:159`）；实际两个键的唯一读点是工具注册（`apps/agent.js:759/761`）。
- `#知识库添加`（`:3330/3335`）仍 `ingestUrl/ingest`，`ingestUrl` 内部直接 `crawlUrl`（`model/agent/knowledge.js:213`），URL 定时刷新仍挂载（`:677/1529`）→ 想「断网/停止入库」的部署关不掉。
- 建议：入库/刷新/定时任务入口统一判 `kb.enable`，抓取入口判 `crawlEnable`；或改注释为「仅控制工具注册」。

#### F13 [P1][X] Stagehand 权限面：默认 `all` + 面板写「仅框架主人」+ 面板无 permission 字段
- yaml `permission: all`（`config.yaml:507`）、代码 `permission==='all' → category:'query'`（`model/stagehand/index.js:44-45`，query=全员）；锅巴 help 却写「**仅框架主人可用**」（`guoba.support.js:321`），且 schema 里没有 `permission` 字段可改回。

- 建议：默认改 `master`；面板补 permission Select；文案与默认二选一改一致。

#### F14 [P1][X] 沙箱 terminal 权限注释仍是旧模型（「仅主人 + 验证码认领」）
- yaml `config.yaml:468-472` 写「仅 terminal 主人可用（验证码认领…）；沙箱化后不再有 #确认 审批」；实际 `model/terminal/exec.js:33` `category:'query'`（全员），锅巴/README 均明写「全员可用」（`guoba.support.js:305`、`README.md:130/940`）。
- 后果：按 yaml 理解安全边界的运维者会低估风险（e2b 开启后任意群成员可执行命令、默认出口全放通）。

#### F15 [P1][L] 面板覆盖仅 25.8%，与 README「图形化编辑全部配置」不符

33. **`agent.toolDiscovery.stableList` 与 `topK/minScore` 的关系**：在 stableList=true 下 topK/minScore 只影响 tool_search 的返回列表与日志，不影响模型可见工具集；yaml/面板未说明这一「搜索仅用于记录/目录」的语义。
34. **云端 TTS `segmentGapMs: 0` 被 `|| 300` 吞掉**（`model/tts/service.js:631`；yaml 三家都写「0=不留空隙」）；IndexTTS 路径（`:441`）0 生效 → 同一键两种语义。

36. **`kb.crawl.execution=sandbox` 在 `sandbox.mode≠e2b` 时回落宿主 crawl4ai**（`model/crawl/index.js:439-440`），与 yaml「沙箱未就绪即降级纯 HTTP fetch，**不改跑宿主 crawl4ai**」相反 → 为「不在宿主跑浏览器」而选 sandbox 的用户实际在宿主启动浏览器。

38. **`redactSecrets=false` 只关一半发送路径**：最终正文/流式按开关（`apps/agent.js:2373/2300`），但中途播报 `:2351`、run_error `:2583`、`#续跑` `:3593` 无条件脱敏 → 排障时「关=完全明文」不成立。
39. **`isolation.enable=false` 时提醒变群共享**：`apps/agent.js:1621-1622/1695-1696` 用 `scopeUserId=__group__:<gid>`，`model/agent/schedule.js:398/460` 提醒按该 scope 存取 → 全群共享；而 yaml 明写「提醒/笔记/人设始终按用户」（笔记确实按用户，提醒不成立）。
40. **`maxToolResultChars` 注释「可放宽到 12000」与实际不符**：声明了 `meta.resultCap` 的工具不读全局（`Agent.js:2350`），实际散落硬编码 8000（群公告）/12000（抓取/群记录）/14000（合并转发）/18000（Enka）/48000（子代理）→ 调大全局对被声明工具无效。
41. **`humanize.allowedReadTools` 只按工具名黑名单过滤**（`model/humanize/default-config.js:88`、`apps/humanize.js:83`），不看 `category/meta.sideEffects`：`web_download`（`category:'system'`，会写盘+出网）名字不在黑名单 → 管理员把它加进「只读白名单」后伪人 Planner 会拿到真实执行能力且绕过 RBAC/confirm。
42. **`vision.maxTokens` 会被模型列表条目的 `maxTokens` 静默覆盖**（`apps/agent.js:1326-1329`），yaml 未声明优先级 → 按 yaml 调视频报告上限不生效。
43. **`sandbox.audit` 承诺「每条命令 + 退出码」只兑现一半**：成功命令不记退出码（`model/terminal/exec.js:71` 仅失败时补记），工具转命令链路（`model/sandbox/bridge.js:87-89`）完全无结果字段（置信度中，若「审计日志」仅指控制台则属文案问题）。
44. **`confirmTimeout: 300` 无单位注释**（`config.yaml:212`）→ 代码按秒 ×1000（`apps/agent.js:673`），易被当毫秒填 300000；`agent.policy.categoryMin:` 空值无说明（「留空=内置」语义可接受，但 yaml/文档无示例、任意 rank 无校验）——两条文档缺口，不单列更细。

## 五、已核实「不是问题」的疑似项（避免误修）

1. **镜像字段未被面板暴露**：`agent.protocol/preset/baseURL/apiKey/model` 不在锅巴 schema；`Config.save` 先 `normalizeBaseModel` 回填，因此面板不会写坏镜像（风险只在引用失效时的静默分叉，见 F2）。
2. **`compaction.enable=true` + `contextWindow` 留空不是死路径**：无窗口时按消息数水位 30→18 触发压缩，归档在 count 模式同样生效（`Agent.js:1619-1635`、`compact/index.js:286/345`）。
3. **`thinkingAuto` 覆盖手动、模型级 thinking 优先的声明与实现一致**（`apps/agent.js:1131/1163-1167`、`Agent.js:580/1878-1889`）——问题只在「保存时删配置」（F18）。
4. **`humanize.enable=true && groups=[]` / `groupWorld.enabled=true && groups=[]` 不开启** 确有代码强制（`humanize/default-config.js:152-155`、`groupworld/default-config.js:71-80`）。
5. **SelfState 红线字段**（`exposeNumericState`/`noCrossUserSpillover` 等）虽被 `validateSelfStateConfig` 强制，但字段本身无人消费、红线硬编码在 `projector.js/prompts.js` → 配置无效但行为安全，不单列。
6. **yaml 所有非空默认值都在面板 InputNumber 边界内**；历史 `maxTurns` 面板 max=100 截断默认 200 已修复（现 max=1000）。
7. **Select 枚举**逐项核对：`trigger/chatPermission/guardAction/guardSensitivity/reply.mode/thinkingAuto.classifier/toolDiscovery.method/research.permission/sandbox.mode/stagehand.mode/stagehand.region/kb.crawl.engine/fallbackProtocol` 均一致，唯一不匹配是 `kb.crawl.execution`（F5）。
8. **Web 配置中心 423 个 `form.*` 绑定全部落在 yaml 叶子上**（除 2 个 computed 包装），没有「Web 独有脏字段」；锅巴 143 field 中 3 个派生字段都有双向特判。
9. **`model/{humanize,groupworld,selfstate}/default-config.js` 与 yaml 当前逐值一致**（脚本比对 56/36/40 个键零差异）——是**重复真源**（维护风险）而非当下漂移，列入治理建议。

## 六、根因与治理建议（按投入产出排序）

1. **给配置加「单一 schema + 自动对账」**：
   - 新增 `scripts/check-config-drift.mjs`：解析 yaml 叶子 × 锅巴 field × Web 绑定 × 代码读点，做四方差集并在 CI 失败。本次排查的 `audit/tools/inventory2.py` 即雏形（已能输出 542/143/423 三方差集与「零属性读取」候选）。
   - 两个面板若继续并存，**必须由同一份字段表生成**（label/默认值/枚举/min-max/help 只写一次），否则同类漂移会持续复发。
2. **把归一逻辑下沉到 `Config.js`**：新增统一 `normalize(data)` 处理镜像字段、thinking 互斥、数组/布尔强转、数值空值；`load / reload / save / 面板 setConfigData / PUT /api/config` 全部走同一函数。当前「锅巴在保存时删 thinking、Web 在载入时置 null、第三条写入路径什么都不做」就是分散归一的结果。
3. **保存策略改为「只写差异」+ 默认值版本化**：解决 F16 的快照化；`reload()` 复用 `load()` 的自愈逻辑，避免内存/文件两套真源。
4. **清除代码侧兜底默认（或统一为「取更严」）**：`maxTurns/maxToolResultChars/chatPermission/LoopGovernor*` 四类已确认；引入 `pickNumber(x, fallback)` / `pickBool(x, fallback)` 工具，禁止 `Number.isFinite(Number(x))` 直接判存在（`Number(null)===0` 是本轮唯一 P0 的直接成因）。
5. **安全默认与文案对齐**：Stagehand `permission` 默认 `master`（或改文案为 all）、`chatPermission` 兜底改 `master`、yaml terminal 注释按实际「全员可用 + 出口默认放通」重写，并在 README 用醒目段落说明沙箱权限边界。
6. **父开关语义统一**：默认配置里所有「父关子开」组合逐条加「仅当 X=true 时生效」注释；`comfyui` 关时不再注册指令；`tts.autoReply` 默认随 `enable` 走。
7. **文档同步清单**（一轮改完）：`renderScale`(锅巴)、`contextWindow`(锅巴)、`crawl.execution`(锅巴)、`kb.enable/crawlEnable`(yaml)、`media.passive`(README/代码)、`taskStore`(README)、`vision.model`(README)、`fallback 同 provider`(README)、`persona.dir`(README)、`debug`(三处)、`apiKey 必填 vs 镜像`(yaml/README)、`thinking 形状`(yaml)。
